项目概览

该项目面向 Dota 2 复杂团队博弈场景，研究大模型能否根据当前比赛状态预测队伍下一步宏观动作，例如 Farm、Team Fight、Push Tower、Defend Tower、Pickoff 等。项目重点不是做一个普通分类器，而是用 Qwen2.5-14B 在指令生成范式下完成决策预测，并通过 SFT、GRPO 和 OPD-lite corrected continuation 做后训练。

任务定义

项目设置
输入某一方队伍视角下的当前和近期可见游戏状态事实。
输出在有限动作空间中给出 1 到 2 个团队宏观动作，可附带简短推理。
主指标primary action accuracy，即第一个预测动作是否正确。
集合指标exact action-set match、action micro F1、action macro F1。

V4.6 数据线保留游戏状态事实和有限动作候选集，但移除了 prompt 中可见的标签捷径，例如 decision hints、future summary、label evidence 等，避免模型依赖泄漏线索。

动作空间由统一配置维护，包含 Roshan、Push / Defend Tower、Push Barracks、Team Fight、Pickoff、Vision、Rune、Farm 等宏观团队动作。模型输出通过 answer 标签解析，保证训练、推理和评测使用同一套格式约束。

OPD-lite 口径

OPD-lite 使用 corrected target continuation 做轻量延续训练，是 OpenClaw-inspired 的轻量桥接版本。项目中也跑通了真正 token-level OPD appendix，但 strict holdout 略低于 OPD-lite 起点，因此作为负结果分析，不把它表述为主贡献。

实现细节

训练代码围绕统一的动作解析和评测函数展开，避免 SFT、GRPO、OPD-lite 各自使用不同答案口径。核心公共逻辑包括答案解析、目标动作读取、预测文本读取和多指标评测。

模块具体实现
动作解析从最后一个 answer 标签中抽取文本，支持逗号、中文顿号、分号、换行等分隔，并去重、识别 unknown actions。
目标读取优先读取人工动作标签，其次组合主动作和辅助动作，保证训练集和生成结果可统一评测。
评测统计输出 valid format rate、primary accuracy、exact set、micro / macro F1、confusion matrix 和 bad examples。
切片分析对类别 support、net gain、负迁移和混淆对进行分析，用于解释 OPD-lite 的收益来源。

SFT LoRA

SFT 阶段使用 TRL SFTTrainer 和 PEFT LoRA，对 Qwen2.5-14B 做指令输出格式对齐。训练流程将 user prompt 与 assistant target 拼成 chat template，支持 bf16 / fp16、4-bit、gradient checkpointing、LoRA r / alpha / dropout 和 target modules 配置。

GRPO LoRA

GRPO 阶段每个样本用当前策略生成多个候选回答，解析成动作集合后计算 mixed reward，再在同一 prompt 的候选组内做 reward 标准化得到 advantage。更新时只对 response tokens 计算平均 log probability，优化目标为 advantage-weighted policy loss，并配合梯度累积、clip grad、cosine warmup scheduler 和 rollout log。

OPD-lite

OPD-lite 不是完整 token-level OPD，而是把带 hindsight hint 的 corrected target 作为 assistant continuation，继续训练已有 LoRA adapter。训练流程会记录 adapter、样本规模、训练步数和学习率等摘要信息，便于复现实验口径。

误差分析

OPD-lite 主要修复低召回困难类别，尤其是 Team Fight 和 Farm。Strict holdout 上 Team Fight 支持样本 735，net gain +89；Farm 支持样本 496，net gain +82。

主要副作用是部分 Pickoff 和 Defend Tower 类标签迁移为 Farm 或 Team Fight。整体仍然正向，但项目保留了这类负迁移分析，避免只报告单一总分。

这部分分析反过来指导 reward 设计：例如 Team Fight 召回不足时，可以在类别定向 reward 模式中对正确 Team Fight 加奖励，对把目标类误判成 Team Fight 或把 Team Fight 误判成目标推进类做轻量惩罚，从而验证类别定向 reward 是否会牺牲全局表现。
