竞赛概览

DataAgent-Bench 要求 Agent 在给定 CSV、JSON、SQLite、Markdown 等多源上下文中自动读数、查表、计算，并生成标准答案表格。Hidden test 只提供 input，不提供 gold output，因此 Agent 必须具备可靠的数据发现、schema linking、执行验证和最终提交能力。

任务特点

  • 上下文异构：同一任务可能同时包含 CSV、JSON、SQLite / DB、Markdown 或普通文档。
  • 问题复杂：需要跨文件、跨表、跨字段推理，且经常涉及统计口径理解。
  • 输出严格：最终答案必须是标准表格，格式错误会直接影响得分。
  • 评测真实：每个任务输出轨迹记录和预测表，便于复盘每一步工具调用。

Agent 设计

我基于官方 ReAct Baseline 与 Qwen3.5-35B-A3B 构建可控 Data Agent，把复杂数据问答拆解为 Discovery、Schema Linking、Execution、Verification、Submission 五个阶段。

Agent 主循环采用 JSON Schema 约束的 ReAct 协议。模型每一步必须输出 think、action、action_input 三个字段；响应 schema 将 action 限制在已注册工具枚举内，解析失败则记录错误 step 并进入重试自修复。

阶段作用
Discovery扫描任务上下文，识别可用文件、数据库和文档。
Schema Linking将自然语言问题中的业务字段映射到真实列名、表名和文件路径。
Execution执行只读 SQL、Python 计算或文件读取。
Verification检查统计口径、结果范围和答案格式。
Submission通过 finishtask 提交标准表格答案。

工具体系

工具用途
listdir列出 context 下文件和目录，支持控制扫描深度。
inspectfile读取 CSV / JSON / 文档等文件的结构、列名、样例和行数信息。
readfile按路径读取文本或结构化文件内容，用于核对字段含义和证据。
inspect_sqlite_schema查看 SQLite / DB 表结构。
execute_context_sql在 context 内执行只读 SQL。
python在任务 context 内执行受限 Python 计算。
finishtask提交最终标准答案表格。

JSON Schema 约束的结构化 Action 相比自由文本工具调用更容易做 action 枚举校验、参数解析、错误定位和 trace 复盘。

工具注册表负责管理所有工具能力。每个工具实现统一接口，声明 name、description、input_schema、permissions 和 handler；工具描述会被注入 system prompt，执行器则按 action 名称分发执行。

运行时实现

运行层会加载 DABench task、创建任务级输出目录、初始化 Agent、执行主循环，并把结果持久化为轨迹记录和标准预测表。

上下文窗口监控 对长 Observation 进行截断，并监控 128K 上下文窗口的 used / remaining tokens 与 message_count，防止多步工具结果挤占推理空间。
业务语义增强 从 500 条 Evidence / SQL 样本中抽取业务规则和跨表关系，构建覆盖 11 个数据库、75 张表的语义文档；将 business rules、measures、scenario hints 和 candidate tables 注入 task prompt，但最终字段仍以工具观测为准。
任务并发与超时 提交流程支持从环境变量读取模型、输入、输出、日志、并发数和任务超时配置，使用线程池批量跑任务；单任务则以 subprocess timeout 兜底。
结果落盘 AgentRunResult 会序列化 step records、answer、failure_reason 和 succeeded；若 answer 存在，运行层会额外写出标准预测表供官方评测。

安全与复盘

  • SQL 使用只读连接，并只允许 SELECT / WITH / PRAGMA 语句，避免误写数据库。
  • Python 子进程设置 30 秒超时，避免无限循环或长时间阻塞。
  • 任务级 max_steps 与 task_timeout 控制 Agent 长程执行风险。
  • Python 工具通过 audit hook 限制文件写入范围，只允许写到 task output directory。
  • 保留轨迹记录、预测表和汇总报告，用于失败复盘和 prompt / tool 策略迭代。

Python 工具把代码放到独立 multiprocessing 子进程运行，捕获 stdout / stderr，并安装 filesystem guard：读操作可以查看 context，写操作必须落在任务输出目录，chmod、mkdir、remove、rename 等变更操作都会经过路径审计。
