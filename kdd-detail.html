冠军方案分析

复现冠军方案后，对完整求解链路进行拆解，重点分析数据加载、SQL 查询、Python 计算、文档检索和答案生成之间的调用关系。

统一数据层基于 DuckDB 统一处理 CSV、JSON、数据库与结构化文档，减少不同文件类型之间的工具切换。
Solver 链路分析 SQL 与 Python Solver 的职责边界，区分关系查询、聚合统计与复杂计算。
冗余定位通过运行轨迹识别简单任务中的过度检索、重复读取、无效模型调用与上下文膨胀。

自适应路由

设计任务路由器，根据题目是否涉及文档检索、复杂计算、多表关联与排序筛选判断任务复杂度。简单任务直接进入求解，复杂任务按需启用业务知识检索和输出约束。

判断信号路由策略
单表读取、简单筛选或直接聚合直接使用 DuckDB / SQL 求解，避免额外检索和多轮模型规划。
复杂计算或统计转换启用 Python Solver，并只传递必要字段与中间结果。
多表关联、排序与组合条件启用结构分析和跨表查询，约束表、字段与连接路径。
业务文档或隐含规则依赖按需检索业务知识，并将证据与输出格式要求注入求解阶段。

优化原则：让任务复杂度决定工具与上下文预算，简单任务减少模型调用，复杂任务保留必要的检索、计算与输出约束。

数据与求解

任务解析 复杂度判断 DuckDB 数据加载 SQL / Python Solver 按需知识检索 答案约束与输出
  • 使用 DuckDB 统一组织多源数据，减少文件格式差异对查询逻辑的影响。
  • 将简单关系查询优先交给 SQL，复杂数值计算和自定义逻辑交给 Python。
  • 仅在题目需要业务语义时加载相关文档，避免把完整知识库塞入上下文。
  • 在最终阶段约束答案格式与字段顺序，减少正确计算后的提交格式错误。
