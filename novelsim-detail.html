项目概览

NovelSim 是一个服务器权威的多智能体叙事游戏原型。玩家和 NPC 的自然语言先被解析为候选行动，LLM 只负责高层意图、角色决策与叙事表达，不能直接修改世界；所有事实变化都必须通过工具权限、世界规则、角色认知和因果授权校验，再以原子 StatePatch 提交为可回放的 WorldEvent。

问题与设计原则

生成式游戏若让大模型直接修改世界状态，容易产生不存在的实体或技术、角色使用未掌握的信息、能力越界以及叙事与真实状态互相矛盾等问题。NovelSim 将“生成能力”和“事实权威”解耦：模型可以提出行动，但只有确定性引擎能够提交状态变化。

风险系统约束
世界观幻觉校验实体、时代技术、世界概念、Capability 与 Affordance。
角色知识泄漏按 session 与 character 隔离记忆，并校验角色已知信息和证据链。
状态矛盾所有变化通过结构化 StatePatch 原子提交，由事件版本链维护权威状态。
叙事脱离事实叙事必须引用已提交事件，并通过实体、说话者、认知边界与事件依据检查。

系统架构

玩家 / NPC 意图 候选 Action 规则与认知校验 StatePatch WorldEvent 叙事与前端表现
提议 LLM 基于角色状态、局部观察、记忆与玩家输入，生成符合 Pydantic Schema 的候选行为和工具参数。
校验 ToolRegistry 和规则引擎检查工具权限、实体存在性、世界设定、角色能力、空间位置、已知信息与 Action-Patch 因果关系。
执行 通过校验的行为被转化为原子 StatePatch，并提交为带版本号、因果证据和状态哈希的权威 WorldEvent。
叙事 Narrator 只解释已发生的事件；Web 和 Unity 客户端消费事件流，表现移动、物品、对话、关系和联盟变化。

多智能体流程

每个角色 Agent 运行“感知—记忆检索—决策—工具执行—观察—反思”闭环。角色只看到自身可感知的世界状态与角色隔离记忆，信息通过对话和事件逐跳传播，并保留来源证据，避免全知视角造成知识泄漏。

模块职责
Perception构造角色局部观察，过滤不可见实体和未知事实。
Planner根据目标、关系、记忆和当前状态生成结构化候选行动。
Agent Tools提供移动、交互、物品、对话、信息传播与联盟等受控能力。
Reflection从新事件提炼长期记忆，更新关系与后续决策依据。
Scheduler调度 NPC 行动和回合推进，保证状态版本与事件顺序一致。

长期记忆

记忆系统以 session_id + character_id 严格隔离角色数据，结合 SQLite FTS5 词法检索和 Qdrant 向量检索，并将语义相关度、词法相关度、重要度与新近性组合排序。召回内容携带 source_event_id，用于证据引用、冲突检测和角色认知审计。

运行与可视化

  • 基于事件日志、版本链和状态哈希实现存档恢复、断点续传与剧情回放。
  • 使用 FastAPI 与 Vue 3 构建 Web 控制台，展示角色状态、世界规则、关系图、行为轨迹、工具调用与规则拒绝原因。
  • 接入 Unity 6.3 LTS，支持 NavMesh 移动、场景交互、物品 / 对话 / 联盟 HUD 和可续传事件游标。
  • 提供编译器与创作者流程，可将书籍或场景素材转化为世界包、角色、规则和可运行场景。

系统评测

确定性基线：333 项 Python 回归测试通过，9/9 个固定场景通过；合法工具、预期拒绝、状态回放、信息传播和证据链均为 100%。

安全一致性：非法状态写入、未知实体接受、因果越权提交与角色认知泄漏均为 0；门禁 G0 → G3 的违规放过数由 6 降至 0。

评测结果

真实模型回归20/20 完整运行，18/20 目标成功；14 个提交事件的回放、因果证据、叙事覆盖和结构化事件依据均为 100%。
真实模型调用45 次调用、49,255 Token，P50 / P95 为 10.554s / 16.469s。
强基线盲测与同模型 direct-prompt 强基线为 3–3；不将主观叙事质量表述为领先结论。
