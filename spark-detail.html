研究背景

持续讨论中，人的态度和讨论对象会一起变化。例如自动驾驶讨论从安全延伸到隐私、就业和监管时，参与者会结合新信息重新表达观点。SPARK 研究个体持续交换观点时，立场变化与话题扩展如何共同发生。

项目用具有独立人设、观点和记忆的 LLM Agent 构建仿真环境，逐日保存接触信息、发言和立场，再分析群体分布与话题变化。我以共同第一作者参与 SARA 人设与双层记忆、TES 交互调度与轨迹记录，以及实验和记忆消融分析。

成果发表于 EMNLP 2025 Main。以下介绍包含个体状态更新、群体调度、数据记录和实验分析四条实现链路。

问题与方法设计

问题方法
立场与话题分开研究，难以还原个体变化同一条发言同时记录文本、立场和事件标签，关联人物与时间
角色条件相同，生成行为容易同质化为每个个体初始化身份、Big Five 特质与独立历史
长期交互需要持续状态，完整历史不断增长先摘要当天接触观点，再整合进长期记忆
只有群体总量难以解释变化过程保留接触来源、观点、记忆与立场序列，结合消融和个体轨迹分析

总体架构：SARA 与 TES

模块步骤输出
SARA：立场感知角色 Agent人设初始化 → 收集观点 → 短期摘要 → 长期整合 → 生成发言 → 提交状态记忆、tweet、stance、reasoning
TES：话题演化模拟器创建群体 → 抽取接触对象 → 随机顺序调度 → 记录话题 → 汇总轨迹 → 推进时间接触关系、群体统计、话题记录与仿真检查点
每日主循环：选择接触对象 → 收集最新观点 → 摘要与记忆更新 → 生成新发言和立场 → 记录话题与人物状态 → 下一天

每个个体独立保存身份和历史，群体层负责接触对象、执行顺序与时间推进。108 个 Agent 共享模型服务，各自使用独立的提示上下文和状态。

模块一：SARA 个体状态与双层记忆

步骤 1：初始化身份、观点与历史容器

为每个 Citizen 分配 unique_id，保存姓名、年龄、学历、人格特质、议题和初始观点。姓名通过 names-dataset 采样，年龄使用 random.randrange(18,65)，学历从预设类别中抽取；Big Five 每个维度从对应特质词集合采样，组合成人设描述。

初始群体包含支持、反对、中立各 36 人，从各类别的观点句子集合随机选择初始表达，标签分别映射为 1、−1、0。每个个体维护 opinions、stances、reasonings、contact_ids 和记忆历史，初始长期记忆为空文本。

步骤 2：读取接触对象的最新观点

遍历当天分配的 agent_interaction，读取对方的 unique_id 和 opinions[-1]。当天观点列表追加到 short_opinion_memory，来源 ID 追加到 contact_ids，保留本次更新的信息来源。

步骤 3：生成当天短期摘要

将当天接触的观点按行拼接，与当前议题一起送入摘要提示。模型归纳主要观点及支持、反对、中立倾向，输出几句话的短期摘要；该调用温度设为 0.5。摘要用于整理当天材料，随后进入长期记忆更新。

步骤 4：将新摘要整合进长期记忆

另一次调用同时接收旧长期记忆和当天摘要，要求整合新信息并保持历史连续性，温度设为 1。返回的新记忆暂存为 long_mem，供本轮观点生成使用，随后写回 long_opinion_memory 并追加到 long_memory_full。

短期摘要 = LLM（当前议题，当天接触观点）
新长期记忆 = LLM（旧长期记忆，短期摘要）

步骤 5：组合提示并生成结构化发言

把姓名、特质、学历、旧观点、当前议题和新长期记忆填入观点更新模板。模板引导角色结合既有信念理解新信息，允许受到相反观点影响，并要求发言包含事件话题标签。

请求设置 response_format={"type":"json_object"}，解析返回的 tweet、stance 和 reasoning，将立场转为整数。

字段记录内容用途
tweet观点文本与事件标签作为其他个体后续读取的最新表达
stance−1 / 0 / 1 立场标签统计人物变化与群体分布
reasoning随发言生成的解释文本辅助回溯本轮表达

步骤 6：提交状态与保存输出

将新发言、立场、解释和长期记忆追加到个体历史，保存人物 ID、人设字段及墙钟时间戳；每次读取已有 JSON 数组并追加记录。更新结束后清空 agent_interaction，下一轮重新分配接触对象。

接口包装层最多尝试 30 次，失败后等待 0.5 秒。JSON 解析或字段读取异常时，现有处理返回 tweet='none'、reasoning='none'、stance=0；该处理对统计的影响列于文末局限部分。

模块二：TES 交互调度与话题演化

步骤 1：创建群体与统一实验配置

用 Mesa 的 Model 表示群体，将个体加入 RandomActivation 调度器。五个领域统一使用 108 个 Agent、每天每人接触 3 个对象、运行 14 天；初始支持、反对、中立各 36 人。

步骤 2：抽取当天接触对象

对每个 Agent 排除自身，将其他对象随机打乱，取前 contact_rate=3 个加入其 agent_interaction。每天重新抽样，形成有方向的信息接触关系：A 接触 B 与 B 接触 A 分别由各自抽样决定。

步骤 3：按随机顺序更新个体

群体先为所有个体选好接触对象，再调用 schedule.step() 随机顺序激活。每个 Agent 在自己的 step() 中完成信息读取、两级记忆更新和观点生成。

读取采用执行时的 opinions[-1]。若 A 先更新、B 随后读取 A，B 会接触到 A 当天的新发言；这种顺序更新使信息能够在同一天继续传递。

步骤 4：记录事件标签与话题扩展

生成协议要求发言包含事件相关 hashtag。根据发言中的标签识别新话题，记录首次出现时间及相关发言；后续再次出现时记录其传播。原始议题作为起点，讨论中产生的子话题进入演化记录。

步骤 5：保存人物轨迹与群体统计

人物对象保留接触来源、接触观点、历次发言、立场与长期记忆，JSON 文件保存人物输出。群体通过 DataCollector 采集支持、反对、中立人数，转为 DataFrame 后导出 CSV。

收集器在每天更新前采样，最终个体状态保存本轮更新后的结果；JSON 的时间戳记录实际调用时间。分析时分别使用仿真轮次与墙钟时间定位记录。

步骤 6：推进时间与保存检查点

本轮激活完成后更新群体计数并推进仿真日期，将整个群体状态通过 pickle 保存到带轮次编号的检查点。入口支持指定已有检查点与偏移继续运行，结束后另存完成状态。

贯穿示例：个体一天的更新

以下用自动驾驶讨论说明数据如何流转。

  1. 旧状态：个体此前主要担忧事故责任，长期记忆保存相关顾虑。
  2. 当天输入：接触三个对象，读取交通效率、隐私风险、无障碍出行三类观点，并记录来源。
  3. 短期摘要：归纳当天的便利性支持和隐私、安全争议。
  4. 长期整合：把新信息并入此前的事故责任记忆。
  5. 观点生成：结合人设与旧观点，生成新的发言、立场及解释。
  6. 群体传播：新发言成为后续可读取的观点，相关事件标签进入话题记录。

人物历史把“接触信息—记忆更新—发言表达”串联起来，为群体指标提供可回溯的个体材料。

四项统计指标

指标定义含义
OB：立场偏向最终立场标签均值正值偏支持，负值偏反对；结合类别分布理解均值
OD：立场多样性最终立场标签的总体标准差衡量个体立场的分散程度
TC：话题一致性−Σ Pₜ(k) log Pₜ(k)按话题分布熵计算，低值表示更集中
TD：话题变化KL(Pₜ ∥ Pₜ₋₁)衡量相邻时间片的话题分布变化

实验结果与消融分析

立场与话题的共同变化

立场变化与新话题出现的时间序列呈较强正相关，Pearson r = 0.88。Credulous 与 Skeptical 人格分组的平均 TD 分别为 0.81 和 0.66，表现出不同的话题分布变化程度。

双层记忆消融

配置OD相对完整架构变化
完整双层记忆0.504对照值
移除短期记忆0.300减少 0.204，约 40.5%
移除长期记忆0.309减少 0.195，约 38.7%

移除任一记忆层后，群体立场多样性均下降。短期摘要组织当天观点，长期整合保存跨日信息，两项操作共同影响最终立场分布。

局限与后续方向

仿真角色共享底层模型偏好，人设与接触机制是对社会交互的简化。相关系数反映仿真时间序列的关联，真实社会适用性与因果机制仍需要外部数据和干预实验检验。

摘要过程可能遗漏少数观点，现有解析失败回退为 stance=0 会混入中立统计。后续可增加独立错误状态和合法标签校验，对照原始接触记录检查摘要保真度，并通过多次运行与真实数据校准评估稳定性。
